# SITHIYAMA — Backend

> **සිතියම** · *Every path remembered. Every explorer found.*

Backend for **SITHIYAMA**, an offline-first trail safety system for the hill forests of
Sri Lanka. Hikers lose mobile signal in the Knuckles range and on Horton Plains; when
fog or rain makes them lose the trail they cannot share their position, so rescues start
blind. SITHIYAMA keeps the trail in the phone and the position in the air.

This repository is the **cloud/API half** of the system (Intellicon '26 Buildathon,
Gate 1 → Gate 2, Section 8.1 of the submission: *Java Spring Boot, PostgreSQL with
PostGIS, JWT authentication*). It is the home of the **community route library**, the
**track sync hub**, **trip plans and check-ins**, and the **SOS alert console**.

---

## 1. What the backend does

| Capability | Why it exists |
|---|---|
| **Route library** | Local guides' knowledge is turned into a shared, offline-downloadable record of the path instead of staying in one person's head. |
| **Track sync** | Uploads recordings made with no signal, plus breadcrumb "black box" logs drained from a Companion Node over Bluetooth. |
| **Trip plans & check-ins** | The structured version of "tell someone your plan". Missed check-ins are what escalate a rescue. |
| **SOS alerts** | Mirrors the 22-byte LoRa packet (position + battery) raised by a Companion Node, together with the trail walked, and supports the ranger triage workflow. |
| **Companion Node registry** | Which node is in the field, its firmware, battery and last known position. |

It deliberately **complements** the 119 police hotline. It does not replace official
emergency services.

## 2. Tech stack

| Layer | Choice |
|---|---|
| Language / runtime | Java 21 (Corretto / Temurin) |
| Framework | Spring Boot 3.5 (Web, Data JPA, Security, Validation, Actuator) |
| Database | PostgreSQL 16 + **PostGIS** (spatial geometry columns, GIST indexes) |
| Migrations | Flyway (schema is owned by SQL, `ddl-auto: none`) |
| Auth | Stateless **JWT** (HS256, `jjwt`), BCrypt password hashing, role-based access |
| API docs | springdoc-openapi → Swagger UI |
| Build | Maven (wrapper included — no global Maven needed) |
| Containers | Docker Compose (`postgis/postgis` + the API) |
| Tests | JUnit 5 + MockMvc integration tests (in-memory H2, no Docker needed) |

## 3. Where it sits in SITHIYAMA

```
 ┌──────────────┐   BLE    ┌────────────────┐   LoRa   ┌──────────────────┐
 │ Android app  │◀────────▶│ Companion Node │─────────▶│ Basecamp Station │
 │ (Flutter)    │          │  (RAK4631)     │          │ (laptop + radio) │
 └──────┬───────┘          └────────────────┘          └────────┬─────────┘
        │ sync when online                                     │ relay when online
        ▼                                                      ▼
   ┌──────────────────────────────────────────────────────────────────┐
   │                     SITHIYAMA backend (this repo)                │
   │  route library · track sync · trips/check-ins · SOS console       │
   │                 Spring Boot + PostgreSQL/PostGIS                  │
   └──────────────────────────────────────────────────────────────────┘
```

The app and Basecamp both work **fully offline**; the backend is the optional shared
layer that syncs the route library and the incident record when connectivity returns.

## 4. Quick start (Docker Compose — real PostGIS)

```bash
cp .env.example .env          # set a real JWT_SECRET
docker compose up --build
```

* API: <http://localhost:8080>
* Swagger UI: <http://localhost:8080/swagger-ui.html>
* Health: <http://localhost:8080/actuator/health>

On first start Flyway creates the schema, enables PostGIS, wires the geometry triggers
and seeds the demo data below.

### Seeded demo accounts

| Username | Password | Role |
|---|---|---|
| `guide` | `Password123!` | `ROLE_GUIDE` — owns the three seeded routes |
| `ranger` | `Password123!` | `ROLE_RANGER` — can triage SOS alerts |
| `admin` | `Password123!` | `ROLE_ADMIN` |

Seeded routes: *Dothalugala Summit Trail*, *Riverston Knife Edge* (Knuckles) and
*Horton Plains World's End Loop*.

Try it:

```bash
# Public route library
curl "http://localhost:8080/api/v1/routes?region=Knuckles"

# Radius search 5 km around Riverston (uses PostGIS ST_DWithin)
curl "http://localhost:8080/api/v1/routes?nearLat=7.53&nearLon=80.75&radiusMeters=5000"

# Sign in as a guide
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"guide","password":"Password123!"}'
```

## 5. Run without Docker (H2 development profile)

No Postgres, no Docker — handy for a laptop or CI:

```bash
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev
```

Differences in this profile: schema is generated by Hibernate, Flyway is off, the H2
console is at `/h2-console`, there is no seed data, and radius search falls back to a
bounding-box filter because PostGIS is not present.

## 6. API reference

Base path `/api/v1`. Everything **except** the `GET /routes` endpoints and the docs
requires `Authorization: Bearer <token>`.

### Authentication — `/auth`

| Method | Path | Notes |
|---|---|---|
| `POST` | `/auth/register` | Username or email + password. Returns a token. `ROLE_ADMIN` cannot be self-assigned. |
| `POST` | `/auth/login` | Accepts username **or** email. |
| `GET` | `/auth/me` | The account behind the current token. |

### Route library — `/routes`

| Method | Path | Notes |
|---|---|---|
| `GET` | `/routes` | Filters: `q`, `region`, `difficulty`, `minDistanceMeters`, `maxDistanceMeters`, `nearLat`, `nearLon`, `radiusMeters`, `mine`, plus `page`/`size`/`sort`. |
| `GET` | `/routes/{id}` | Full route: polyline, bounding box, waypoints, tags. `PRIVATE` routes are visible only to their creator. |
| `POST` | `/routes` | Publish a route (body carries `path` ≥ 2 points and optional `waypoints`). |
| `PUT` | `/routes/{id}` | Creator or admin only. |
| `DELETE` | `/routes/{id}` | Creator or admin only. |

Distance and duration are computed server-side (haversine + a default 3 km/h) when the
client does not supply them.

### Track sync — `/tracks`

| Method | Path | Notes |
|---|---|---|
| `POST` | `/tracks` | Upload a recording: `points[]` with lat/lon, elevation, accuracy, battery and timestamps; optional `source` (`APP`/`NODE`/`BASECAMP`). |
| `GET` | `/tracks` | Your tracks (paged). |
| `GET` | `/tracks/{id}` | One track with its full breadcrumb list. |
| `DELETE` | `/tracks/{id}` | Delete your track. |

### Trips & check-ins — `/trips`

| Method | Path | Notes |
|---|---|---|
| `POST` | `/trips` | Plan a trip: route, times, group size, `checkInIntervalMinutes`, emergency contact, members. |
| `GET` | `/trips` | Trips you organise. |
| `GET` | `/trips/overdue` | Trips that have missed their check-in window. |
| `GET` | `/trips/{id}` | Organiser, admin or ranger. |
| `PUT` | `/trips/{id}` | Update a plan. |
| `PATCH` | `/trips/{id}/status?status=ACTIVE` | `PLANNED` → `ACTIVE` → `COMPLETED` / `OVERDUE` / `CANCELLED`. |
| `DELETE` | `/trips/{id}` | Delete a plan. |
| `POST` | `/trips/{id}/check-ins` | Record a proof-of-life ping; re-arms the next deadline and flips the trip to `ACTIVE`. |
| `GET` | `/trips/{id}/check-ins` | Check-in history. |

### SOS alerts — `/sos`

| Method | Path | Notes |
|---|---|---|
| `POST` | `/sos` | Raise an alert: `source` (`APP`/`NODE`/`BASECAMP`/`MANUAL`), position, battery, message, optional `trail[]`. |
| `GET` | `/sos` | Operators (ranger/admin) see every alert; other users see their own. Optional `status` filter. |
| `GET` | `/sos/{id}` | Includes the trail walked, for the Basecamp replay. |
| `POST` | `/sos/{id}/acknowledge` | Ranger/admin: `ACTIVE` → `ACKNOWLEDGED`. |
| `PATCH` | `/sos/{id}/status` | Ranger/admin: `RESOLVED` or `FALSE_ALARM` (with an optional note). |

### Companion Nodes — `/nodes`

| Method | Path | Notes |
|---|---|---|
| `POST` | `/nodes` | Register a node by `deviceCode` (idempotent for the same owner). |
| `GET` | `/nodes` | Nodes you own, with last battery/position. |
| `POST` | `/nodes/{id}/heartbeat` | Report battery, firmware and last known position. |

Errors are always returned in one shape:

```json
{
  "timestamp": "2026-01-01T10:00:00Z",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed",
  "path": "/api/v1/routes",
  "fieldErrors": { "path": "a route path needs at least two points" }
}
```

## 7. How PostGIS is used

Paths travel as portable WKT text (`path_wkt`, `trail_wkt`) plus plain latitude/longitude
columns, and PostGIS keeps a typed, indexed mirror of them:

* `routes.geom`, `track_recordings.geom`, `sos_alerts.geom` → `geometry(LineString,4326)`
* `route_waypoints.geom` → `geometry(Point,4326)`
* All four are indexed with **GIST**.
* Flyway triggers (`sithiyama_sync_linestring`, `sithiyama_sync_point`) populate the
  geometry columns automatically on insert/update.
* Radius search runs in the database with `ST_DWithin` / `ST_Distance` on `geography`,
  ordered by true distance on the sphere.

This keeps the application portable (the same entities run on H2 for tests and the dev
profile) while the production database gets real spatial indexing. The radius query is
gated by `sithiyama.spatial.enabled`; when it is `false` a bounding-box filter is used.

## 8. Configuration

| Property | Env var | Default |
|---|---|---|
| `spring.datasource.url` | `DB_URL` | `jdbc:postgresql://localhost:5432/sithiyama` |
| `spring.datasource.username` | `DB_USERNAME` | `sithiyama` |
| `spring.datasource.password` | `DB_PASSWORD` | `sithiyama` |
| `sithiyama.jwt.secret` | `JWT_SECRET` | dev-only value (≥ 32 bytes, override it) |
| `sithiyama.jwt.access-token-ttl` | — | `PT12H` |
| `sithiyama.spatial.enabled` | — | `true` |
| `server.port` | `SERVER_PORT` | `8080` |

Active profiles: default (PostgreSQL/PostGIS), `dev` (H2), `test` (H2).

## 11. Scope

**Shipped here:** the route library, track sync, trip plans and check-ins, SOS raise and
triage, node registry, JWT auth and docs.

**Deliberately not in scope (matching the submission):** mesh relaying, encrypted
payloads, iOS, downloadable map manager, voice guidance. The optional on-device fall
classifier and LLM trail summaries live on the app/AI side.
